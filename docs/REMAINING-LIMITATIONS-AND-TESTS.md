# Remaining limitations – test before production

This is a substantial upgrade, not a guarantee of zero edge cases. Please test these cases before describing every feature as 100% compatible.

1. **Annotate PDF** – The browser workspace supports highlight, underline, strike-through, freehand pen, line, arrow, rectangle, ellipse, text, sticky-note/comment and PNG/JPG image placement with multi-page navigation, undo and export. Exports are flattened into page content, not retained as separate editable annotation objects. Rotated pages, unusual crop boxes, transparency, long note text, image placement and very large page dimensions need testing.
2. **PDF to Excel** – Uses PDF.js text coordinates, repeated column starts, gap-based row grouping and optional Tesseract OCR. It is not iLovePDF/Solid Documents' proprietary algorithm. Merged cells, border-only tables, multi-line cells, nested tables, irregular columns and scans with skew/noise may need manual correction. Validate all numbers/dates/totals.
3. **PDF to Word** – Reconstructs text, rough formatting and table rows into DOCX. It cannot faithfully recreate every font, image, chart, floating shape, page break or complex layout. OCR text may contain recognition mistakes.
4. **PDF to PowerPoint** – Editable text mode creates text boxes; it does not turn every source vector, image, chart or diagram into editable native slide elements. Visual mode is high-fidelity but page images are not individually editable.
5. **Fill & Sign** – Standard AcroForm fields supported by pdf-lib work; XFA forms, unsupported widgets, unusual appearances, and complex field calculation scripts may not. PAdES signing requires the signer's authorized PKCS#12 certificate, its password and the online Gotenberg engine. Hardware-token certificates that cannot be exported to PKCS#12 are not supported by this upload flow. Certificate-chain trust depends on the recipient PDF reader. PAdES output alone does not guarantee legal acceptance in India or replace a regulated eSign/DSC workflow; check the receiver's requirements. Do not modify a signed PDF after signing.
6. **Office to PDF / HTML to PDF / PDF-A / Protect / Unlock** – Requires a separate Gotenberg 9 container with both Chromium and LibreOffice modules. A successful page build does not prove this engine is configured. Office fonts, charts, print areas and pagination can differ. HTML scripts and external resources are intentionally disabled/stripped for safety. PDF/A remediation can leave non-zero residual issues; run an independent validator. PDF permission flags are advisory in some readers, so they are not a substitute for encrypting sensitive content.
7. **Chat with PDF / AI Summarize** – Requires a server-side OpenAI API key and may incur usage charges. Extracted text (not the original PDF binary) is sent to the configured provider, up to the route's 65,000-character cap. Scanned documents must be OCR'd first. Avoid confidential documents unless the site owner has reviewed provider/data-handling terms. The model can still misread a table or omit context; verify important answers against the source. The current per-process rate limit is not a distributed quota; production sites should also enforce limits at the gateway or with a shared store.
8. **Existing `/pdf/edit`** – Explicitly excluded from this update, per request.

## Recommended test PDFs

Use copies with non-sensitive content: (a) 2-page text PDF, (b) scanned English page, (c) scanned Hindi page, (d) 4-column table with merged header, (e) portrait + landscape mixed PDF, (f) AcroForm with text/dropdown/checkbox, (g) rotated page, (h) PDF with embedded image and transparent graphics.
